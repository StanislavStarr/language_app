# Alembic migration

## Steps

1. Change/add SQLAlchemy models first; make sure the module's `models.py` is imported in
   `alembic/env.py` model registry.
2. `make up` (DB running), `make migrate` (DB at head).
3. Generate: `make migration name=<snake_case_description>` (wraps
   `uv run alembic revision --autogenerate -m "<name>"`).
4. **Open the generated file and fix it.** Autogenerate is a draft. Check:
   - every expected table/column/constraint is present and nothing unrelated is touched;
   - `server_default` and nullability match the model;
   - enums: created with explicit `sa.Enum(..., name="...")`, dropped in `downgrade`;
   - extensions: `op.execute("CREATE EXTENSION IF NOT EXISTS vector")` (only in the first migration);
   - pgvector column: `sa.Column("embedding", Vector(512), nullable=False)` with `from pgvector.sqlalchemy import Vector`;
   - HNSW index (not autogenerated):
     ```python
     op.create_index(
         "ix_book_chunk_embedding_hnsw",
         "book_chunk",
         ["embedding"],
         postgresql_using="hnsw",
         postgresql_ops={"embedding": "vector_cosine_ops"},
     )
     ```
   - generated tsvector:
     ```python
     sa.Column(
         "search_vector",
         TSVECTOR(),
         sa.Computed("to_tsvector('english', text)", persisted=True),
     )
     ```
     plus `op.create_index(..., postgresql_using="gin")`;
   - trigram index: `postgresql_using="gin", postgresql_ops={"normalized_text": "gin_trgm_ops"}`;
   - partial unique index: `postgresql_where=sa.text("status = 'active'")`;
   - data migrations use `op.execute` / `op.bulk_insert` with literal data, never import app models.
5. Implement `downgrade()` fully (drop indexes before tables, drop enums last).
6. Verify round-trip:
   ```bash
   cd backend
   uv run alembic upgrade head
   uv run alembic downgrade -1
   uv run alembic upgrade head
   ```
7. Run `make backend-check` (tests run migrations on the test DB).

## Rules

- One migration per logical change; descriptive name (`add_book_chunk_with_vector_index`).
- Never edit a migration that has been applied anywhere except your local DB.
- Large backfills run in scripts (`backend/scripts/`), not in migrations.
- Neon free tier is 1 GB: think about row size for big tables (lexicon, chunks) and mention it in the plan.
