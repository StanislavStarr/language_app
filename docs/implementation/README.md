# План реализации English Vocabulary App

Это рабочая навигация по пошаговому плану. Продуктовые и архитектурные решения зафиксированы в
`[english_vocabulary_app_plan.md](../../english_vocabulary_app_plan.md)` — этот документ не спорит с ним,
а превращает его в последовательность конкретных действий.

## Как пользоваться

Шаги пронумерованы **глобально от 1 до 72** и идут строго по порядку. Каждый шаг оформлен одинаково:

- **Цель** — что появится в проекте после шага;
- **Файлы** — что создаём или меняем;
- **Действия** — команды и код;
- **Проверка** — как убедиться, что шаг выполнен;
- **Коммит** — сообщение коммита.

Не переходите к следующему шагу, пока не прошла «Проверка». Это единственная защита от ситуации,
когда ошибка обнаруживается через три дня в совершенно другом месте.

Если по ходу шага непонятна конструкция языка или фреймворка — идите в соответствующий ликбез
(файлы 01 и 02), там объясняется «почему так», а не только «что напечатать».

## Ключевые технические решения этого плана

Эти решения зафиксированы один раз и действуют во всех документах. Если решите изменить — меняйте
здесь, чтобы не возникло двух конкурирующих подходов.


| Область                        | Решение                                                                    | Почему                                                                                         |
| ------------------------------ | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Структура                      | Monorepo: `backend/`, `frontend/`, `bot/`, `infra/`, `docs/`               | Один деплой, одна история изменений                                                            |
| Python                         | 3.13, менеджер пакетов `uv`                                                | `uv` быстрее pip в разы и держит `pyproject.toml` + lock-файл                                  |
| Backend                        | FastAPI, async SQLAlchemy 2.x + `asyncpg`, Alembic, Pydantic v2            | Из продуктового плана                                                                          |
| Фоновые задачи                 | Celery 5.6 + Redis, внутри задач `asyncio.run(...)`                        | Celery синхронный, но провайдеры и БД асинхронные                                              |
| Frontend                       | Angular 22, standalone, signals, zoneless, Vitest, SCSS                    | Актуальный Angular; Karma и Jest в 22 удалены                                                  |
| Формы                          | Angular Reactive Forms                                                     | Так зафиксировано в правилах проекта; Signal Forms в 22 стабильны, но не смешиваем два подхода |
| Аутентификация                 | Telegram `initData` → серверный JWT в заголовке `Authorization`            | Клиенту нельзя доверять                                                                        |
| Словарь (основной)             | Yandex Dictionary API (`en-ru`)                                            | Даёт перевод, часть речи и транскрипцию одним запросом, ключ бесплатный                        |
| Словарь (дополняющий)          | Wiktionary REST API                                                        | Английские определения, без ключа                                                              |
| Аудио                          | Wikimedia Commons + конвертация `ogg → mp3` через `ffmpeg`                 | iOS WebView не воспроизводит ogg                                                               |
| AI                             | OpenAI Responses API со structured outputs, модель из переменной окружения | Модельный ряд меняется часто, имя модели не хардкодим                                          |
| Поиск опечаток                 | PostgreSQL `pg_trgm` + `similarity()`                                      | Не требует новых зависимостей                                                                  |
| Защита от двойной AI-генерации | Unique constraint + Redis-лок `SET NX EX`                                  | Общий кэш `MeaningContent` должен генерироваться один раз                                      |
| Лимиты                         | Собственный Redis-счётчик в FastAPI-зависимости                            | Одна зависимость вместо библиотеки                                                             |
| Бот                            | `aiogram` 3.x, только `/start`                                             | Минимальная точка входа                                                                        |

## Оценка времени

План рассчитан на 3–4 часа в день, около 110 часов за месяц. Это плотно, но выполнимо при одном условии:
**ничего из раздела «Что НЕ входит в MVP» продуктового плана не добавляется по ходу работы.**
Любая идея улучшения записывается в `docs/post-mvp.md` и не реализуется сейчас.

Если график начинает отставать, режьте в таком порядке:

1. Wiktionary-провайдер (шаг 31) — работайте на одном Yandex Dictionary плюс AI;
2. конвертация аудио (шаг 32) — выпускайте карточки без звука;
3. E2E-тесты (шаг 64) — оставьте один сценарий вместо трёх.

Никогда не режьте: валидацию `initData` (14), миграции (11), лок на генерацию AI-контента (38),
бэкапы (66). Это то, что потом невозможно доделать «по-быстрому».
