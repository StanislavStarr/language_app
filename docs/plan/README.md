# План разработки MVP (для Claude Code)

> Что строим — [PRODUCT.md](../PRODUCT.md). Как устроено — [ARCHITECTURE.md](../ARCHITECTURE.md).
> Почему так — [DECISIONS.md](../DECISIONS.md). Правила кода — `CLAUDE.md`, `backend/CLAUDE.md`,
> `mobile/CLAUDE.md`.

Этот план — **не пошаговая инструкция с кодом**, а набор задач с контекстом и критериями приёмки.
Код пишет агент, человек ставит задачу, проверяет результат и принимает решения.

Итого ~155 часов: около 6 недель при 3,5–4 часах в день. Порядок фаз фиксирован:
добавление слов (2) раньше читалки (3), читалка раньше обучения (4).

**Если отстаём, режем в таком порядке:** неправильные глаголы (T4.2, T4.5) → FB2-парсер (часть T3.2)
→ Free Dictionary fallback (T2.5) → история вопросов в «Спроси книгу» (часть T5.3).
**Никогда не режем:** валидацию входов и файлов, миграции, блокировку генерации `meaning_content`,
защиту от спойлеров, лимиты AI, тесты state machine занятия.

## Формат задачи

```markdown
### T2.7 — Короткое название                       ~4 ч   [ ]
**Цель:** что появится в продукте или коде.
**Контекст:** какие разделы документов и какой код прочитать перед началом.
**Сделать:** что должно быть реализовано (не как писать код).
**Приёмка:** проверяемые критерии — по ним задача закрывается.
**Тесты:** какие тесты обязательны.
**Не делать:** границы задачи.
**Skills:** какие skills из .claude/skills применить.
```

Статус задачи — чекбокс в заголовке: `[ ]` → `[~]` (в работе) → `[x]`. После закрытия агент
дописывает под задачей строку `> Итог: …` — 1–3 предложения о том, что сделано и что отличается
от плана.

## Как работать с Claude Code

1. **Одна задача — одна сессия.** Перед новой задачей `/clear`. Длинная переписка ухудшает качество.
2. Запуск задачи: `/run-task T2.7`. Skill `run-task` заставляет агента прочитать задачу и контекст,
   показать план, реализовать, прогнать проверки, вызвать ревьюера и обновить статус.
3. **Задачи ≥ 3 ч** — сначала план (Plan mode, `Shift+Tab`), правки плана, потом реализация.
4. **Проверки перед «готово»:** `make backend-check` и/или `make mobile-check` — зелёные.
   Для UI-задач — ручная проверка на телефоне через Expo Go (агент пишет, что именно проверить).
5. **Ревью:** агент вызывает subagent `code-reviewer`; замечания уровня «must fix» исправляются
   в той же задаче.
6. **Коммит:** один логический коммит на задачу (или несколько, если задача большая):
   `feat(lexicon): lookup with sense selection [T2.7]`. Conventional commits. Агент коммитит только
   по команде человека или если это явно разрешено в сессии.
7. **Расхождение с документами.** Если реализация требует изменить решение — агент останавливается,
   предлагает правку `ARCHITECTURE.md`/`DECISIONS.md`, и после согласия обновляет документ в том же коммите.
8. **Новые идеи** — в `docs/backlog.md`, не в код.
9. **AI-фичи:** изменения промпта, модели или параметров поиска — только с прогоном evals
   «до/после» (skill `llm-feature`, subagent `eval-analyst`).

## Готовность MVP

1. APK устанавливается на Android; приложение открывается в Expo Go на iPhone.
2. Первый запуск: анонимный вход и onboarding.
3. Ручное добавление слова и фразы: значения, рекомендация по контексту, AI fallback, опечатка.
4. Карточка готовится в фоне: перевод, IPA, аудио, определение, пример; частичная деградация работает.
5. Темы: создать, изменить, удалить; слово в нескольких темах.
6. Загрузка EPUB, FB2 и TXT; понятные ошибки для битых и неанглийских файлов; демо-книги доступны.
7. Читалка: главы, прокрутка, шрифт, тема, позиция чтения сохраняется и восстанавливается.
8. Тап по слову: лемма, значение в контексте, добавление в словарь; выражение через выделение.
9. Сохранённые слова подсвечиваются в тексте; из карточки можно вернуться к месту в книге.
10. Занятие: 4 этапа для слов, 3 для фраз, неправильные глаголы, восстановление после закрытия.
11. «Спроси книгу»: ответ со ссылками на абзацы, без спойлеров, на простом английском или русском.
12. Лимиты AI работают; при исчерпании — понятное сообщение.
13. Удаление книги и аккаунта.
14. Backend на Render + Neon; холодный старт обрабатывается в приложении.
15. Evals: отчёты `sense_selection`, `meaning_content`, `book_qa` с метриками не ниже целевых
    (ARCHITECTURE.md §9).
16. CI зелёный; README с архитектурой, метриками evals и демо.
