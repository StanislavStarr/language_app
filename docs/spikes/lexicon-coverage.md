# Спайк T2.1: покрытие данных Wiktextract

**Статус:** завершён. Все цифры получены полным прогоном `backend/scripts/explore_wiktextract.py` на двух файлах kaikki.org (English edition, enwiktionary от 2026-10-01 по данным страницы `kaikki.org/dictionary/rawdata.html`):

- «общий» английский дамп `kaikki.org-dictionary-English.jsonl` (3,43 ГБ, 1 499 161 запись, прогнан ранней версией скрипта без фильтров);
- «сырой» дамп `raw-wiktextract-data.jsonl.gz` (3,08 ГБ gz, ≈ 24,8 ГБ распакованный, 11 121 531 запись, из них английских 1 499 161).

Проход по «сырому» дампу занимает около 2 минут (отбор английских строк по подстроке `"lang_code": "en"` до разбора JSON; подстрока подходит к этому дампу, её надо перепроверить при смене формата). Список слов: `wordfreq`, `top_n_list("en", N)`.

## 3. Размер таблиц

Оценка: строки × средняя длина + накладные расходы + индексы (btree и GIN trigram). Допущения: накладные расходы строки 48 байт, фиксированные поля `lexeme` 90 байт, `lexeme_form` 24, `meaning` 40, `translation` 24; индекс btree добавляет 16 байт на запись; trigram-индекс — трёхкратный размер текста; в `meaning` берётся последняя глосса значения; сжатие TOAST не учтено; таблицы `meaning_content` и `sense_selection` не включены. Это оценка порядка величины (калибровка по реальной БД — в T2.3).

## 5. Структура данных, важная для импорта

- Переводы лежат на уровне статьи (`translations`), а не внутри значений; с значением их связывает короткая подпись `sense` (например, `institution`). Сопоставление подписи с глоссой (все содержательные слова подписи входят в глоссу последнего уровня) привязывает **≈ 70%** русских подписей. Ручная проверка 30 случайных пар показала **28 верных из 30** (≈ 93%, ±9%); ошибки: `blue` (подпись `colour` взята у другого значения) и `spoil` (подпись `to ruin` подошла соседнему значению). Показатель — доля подписей, нашедших хотя бы одно значение, не полнота привязки по переводам.
- Формы: у лемм есть `forms` (`{form, tags}`, есть мусорные `no-table-tags`), у словоформ — записи с `form_of` в значениях. Форма считается «разрешённой», только если её лемма найдена среди слов a–z выбранного N.
- Произношение: `sounds` с `ipa` и `mp3_url`, теги региона; US-IPA есть у 48% лемм топ-30k, поэтому берётся первое IPA с предпочтением US.
- Ключ `word` в строках дампа не первый: разбор должен быть полным. Английские строки составляют 13% «сырого» дампа.

## 6. Рекомендация

1. **Источник:** «сырой» дамп `raw-wiktextract-data.jsonl.gz`, потоково, с отбором английских строк до разбора JSON.
2. **N = 60 000** (значение по умолчанию из ARCHITECTURE §6.1 сохраняется). Данные не выбирают N однозначно: все доли монотонно падают с ростом N. Основание выбора: слова топ-30k покрывают 94,4% текста, топ-60k — 95,8%, топ-100k — 96,4%, а запросы читателя уровня A2–B2 приходятся на редкие слова «хвоста»; размер при 60k (≈ 50 МБ плюс фразы) далёк от бюджета. N = 100k стоит ещё ≈ 12 МБ и добавляет 0,6 п.п. покрытия текста, но доля лемм с русским переводом падает до 47%. Параметр `--top-n` остаётся настраиваемым; пересмотреть по метрикам реального использования.
3. **Фильтры:** только слова a–z; не брать `pos = name` и записи без значений; не больше 8 значений на часть речи; значения-формы (`form_of`) не импортировать как значения, а превращать в `lexeme_form` (только если лемма входит в импортируемый набор).
4. **Фразы:** импортировать фразовые глаголы, идиомы и прочие фразы, у которых все слова входят в топ-30k (27 828 уникальных); остальные многословные записи не брать.
5. **Переводы:** брать из «сырого» дампа. Подписи, не нашедшие значения (≈ 30%), прикреплять к первому значению соответствующей части речи (эта стратегия пока не проверена). Значения без перевода (около 80% всех, больше у редких слов) переводит AI при первом обращении и кэширует в общей таблице: стоимость растёт с реальными запросами, а не с размером словаря.
6. **Аудио:** `mp3_url` есть у 73% лемм топ-60k; для остальных звук подтягивается из Free Dictionary (T2.5).
