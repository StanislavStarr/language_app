# Backlog (после MVP)

Идеи, которые появились по ходу разработки MVP. Сюда записываем, **не реализуем** до конца MVP.
Плановый post-MVP список — в [PRODUCT.md §8](PRODUCT.md).

Формат: `- [дата] идея — откуда взялась (задача/интервью) — ценность`

## Идеи


- `WWW-Authenticate: Bearer` в ответах 401 (RFC 6750).

- Загрузка книг (T3.x): `createAuthMiddleware` клонирует каждый запрос для повтора после 401, для больших multipart-тел это удваивает буфер; исключить эндпоинт загрузки или повторять вручную.
- `unwrap` рассчитан на ответы с телом; для 204 (`DELETE`) добавить отдельный вариант, когда появится первый такой эндпоинт на клиенте.

- Адрес API на телефоне: порт и IP в `mobile/.env` легко перепутать; показывать `env.apiUrl` на экране ошибки входа в режиме разработки.

- «Удалить аккаунт» в профиле (PRODUCT §6.2, §6.11): нужен `DELETE /users/me` на backend (каскадное удаление) и подтверждение на клиенте.
- Автотест навигатора с `Stack.Protected` (`expo-router/testing-library`): переход онбординг → вкладки после `complete_onboarding`.
- Общие тестовые хелперы mobile (`jsonResponse`, `renderWithProviders`, `USER`): дублируются в нескольких тестах страниц и шлюзов.
