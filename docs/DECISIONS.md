# Архитектурные решения (ADR)

Короткий журнал решений: контекст → решение → последствия. Новое решение — новая запись внизу.
Отменённое решение не удаляется, а получает статус `Заменено ADR-NNN`.

---

## ADR-001. Мобильное приложение на Expo вместо Telegram Mini App

**Статус:** принято, 2026-11-26. Заменяет решение о Telegram Mini App из прежнего плана.

**Контекст.** Долгосрочная цель — мобильное приложение. Платить за Apple Developer Program
($99/год) и за сервер/домен пока не хочется. Android позволяет раздавать APK напрямую; обязательная
верификация разработчиков для сторонней установки вводится с 30.09.2026 только в нескольких странах
(Бразилия, Индонезия, Сингапур, Таиланд), глобально — в 2027 году. На iOS приложение можно запускать
через Expo Go без аккаунта Apple; с мая 2026 Expo Go открывает только проекты своего аккаунта или
организации, в которой состоит пользователь.

**Решение.** Клиент — Expo (React Native). Android — APK через EAS Build. iOS — Expo Go
(тестировщики добавляются в организацию проекта в Expo). Telegram не используется.

**Последствия.** Нет зависимости от Telegram, сразу движемся к целевой платформе. iPhone-тестировщикам
нужен аккаунт Expo. Перед глобальным запуском верификации Android (2027) понадобится аккаунт
Android Developer Console или Google Play.

## ADR-002. Только библиотеки, совместимые с Expo Go

**Статус:** принято.

**Контекст.** Без платного аккаунта Apple нельзя собрать и раздать свой iOS-клиент; Expo Go содержит
фиксированный набор нативного кода.

**Решение.** В `mobile/` разрешены только пакеты из Expo SDK и чистые JS-библиотеки, а также
нативные библиотеки, включённые в Expo Go (reanimated, gesture-handler, flash-list, svg и т. п.).
Перед добавлением зависимости агент проверяет совместимость (`npx expo install`, документация Expo).
Config plugins, требующие prebuild, запрещены.

**Последствия.** Share intent, виджеты, MMKV и подобное — после покупки аккаунта Apple (backlog).

## ADR-003. Анонимный вход по устройству

**Статус:** принято.

**Решение.** `install_id` + `device_secret` в `expo-secure-store` → `POST /auth/device` → JWT на 7 дней.
Модель `auth_identity` поддерживает другие провайдеры.

**Последствия.** Ноль трения на входе и никаких почтовых сервисов. При удалении приложения данные
теряются — предупреждаем в onboarding; перенос аккаунта первым идёт после MVP.

## ADR-004. Свой лексикон из Wiktionary вместо Yandex Dictionary

**Статус:** принято. Заменяет Yandex Dictionary + Wiktionary REST из прежнего плана.

**Контекст.** Yandex Dictionary API недоступен для проекта. Wiktextract (kaikki.org) публикует
машиночитаемый Wiktionary в JSONL: леммы, формы, значения, переводы, примеры, IPA, ссылки на аудио
(в том числе mp3). Лицензия CC BY-SA.

**Решение.** Однократный импорт английской части (ограниченной частотным списком) в PostgreSQL.
Fallback при отсутствии слова — Free Dictionary API (без ключа, только английский), затем AI.
Русский перевод — из Wiktionary, иначе AI. Аудио — прямые mp3-ссылки Wikimedia, без скачивания
и конвертации.

**Последствия.** Lookup без внешних вызовов в большинстве случаев; есть связи форма → лемма для
читалки. Нужна задача-разведка по покрытию русских переводов. Обязательна атрибуция Wiktionary.

## ADR-005. Только PostgreSQL: Procrastinate вместо Celery + Redis

**Статус:** принято.

**Контекст.** Бесплатный Render не даёт фоновых воркеров; Redis — лишний сервис. Celery синхронный,
а код асинхронный.

**Решение.** Очередь задач — Procrastinate в той же базе, воркер в lifespan FastAPI. Блокировки —
`pg_advisory_xact_lock` и unique-ограничения. Лимиты — таблица `daily_usage` + in-memory
rate limit (один инстанс).

**Последствия.** Один процесс и одна база. При горизонтальном масштабировании in-memory rate limit
придётся заменить.

## ADR-006. Книга парсится на сервере в нормализованную структуру

**Статус:** принято.

**Решение.** EPUB/FB2/TXT → главы → абзацы (+ границы предложений) в PostgreSQL. Исходный файл
не хранится (временный `book_upload` удаляется после парсинга). Клиент рендерит абзацы сам,
без WebView и epub.js.

**Последствия.** Простые тап по слову, подсветка и позиция чтения (номер абзаца); одинаковое
поведение на Android и iOS. Форматирование книги (курсив, картинки) в MVP теряется.

## ADR-007. RAG: гибридный поиск, защита от спойлеров, ответы со ссылками

**Статус:** принято.

**Решение.** Чанки по 200–400 токенов по границам абзацев; `text-embedding-3-small` с 512
измерениями; pgvector HNSW + FTS `english`, слияние RRF; фильтр `end_position ≤ позиция чтения`;
structured output с `found_in_text` и `cited_chunk_ids`, проверка ссылок на сервере.

**Последствия.** Дёшево (эмбеддинг книги стоит доли цента), помещается в 1 ГБ Neon, качество
измеряется eval-набором `book_qa`.

## ADR-008. AI-слой: протоколы, версии промптов, кэши, evals

**Статус:** принято.

**Решение.** Бизнес-логика зависит от `AIProvider`/`EmbeddingProvider` (Protocol), не от OpenAI.
У каждой фичи версия промпта, Pydantic-схема ответа, валидация, кэш где возможно и eval-набор.
Модель задаётся переменной окружения. Изменение промпта/модели → прогон evals «до/после».

## ADR-009. Бесплатный хостинг: Render + Neon + EAS

**Статус:** принято.

**Контекст.** Render Free: сервис засыпает через 15 минут простоя, просыпается около минуты,
750 часов в месяц, файловая система эфемерная, фоновых воркеров нет. Neon Free: 1 ГБ на проект,
100 CU-часов в месяц, scale-to-zero, pgvector доступен.

**Решение.** Backend — Render Free (Docker), БД — Neon Free, Android-сборки — EAS Build (free).
Домен не нужен: `*.onrender.com`.

**Последствия.** Холодный старт обрабатывается клиентом; внешний пинг держит сервис активным.
Переезд на VPS — смена переменных окружения и `docker compose`.

## ADR-010. Контракт API: OpenAPI → TypeScript

**Статус:** принято.

**Решение.** FastAPI генерирует OpenAPI; `openapi-typescript` создаёт `mobile/src/shared/api/schema.d.ts`;
запросы через `openapi-fetch`. Ручные дубли типов ответов запрещены.

## ADR-011. Лемматизация: spaCy + формы Wiktionary

**Статус:** принято. Отменяет «лемматизация не входит в MVP» из прежнего плана.

**Причина.** В читалке пользователь нажимает на словоформы («went», «running»). spaCy
`en_core_web_sm` даёт лемму с учётом части речи в предложении; `lexeme_form` из Wiktionary
закрывает неправильные формы и неоднозначности.

## ADR-012. Монорепозиторий `backend/` + `mobile/`, FSD с маршрутами Expo Router вне `src/`

**Статус:** принято. Папки `frontend/` (Angular) и `bot/` удаляются.

**Решение.** Маршруты Expo Router — тонкие файлы в `mobile/app/`, которые только рендерят страницу
из `src/pages`. FSD-слои — в `mobile/src/`: `app`, `pages`, `widgets`, `features`, `entities`, `shared`.
Границы проверяет `steiger`.

## ADR-013. Суточная квота списывается до действия и не возвращается

**Статус:** принято.

**Контекст.** `UsageService.consume` атомарно увеличивает счётчик и коммитит транзакцию до вызова
AI или обработки книги.

**Решение.** Квота расходуется заранее; при сбое самого действия она не возвращается. Вызывать
`consume` нужно первым шагом use case, до другой незакоммиченной работы в той же сессии.

**Последствия.** Пользователь не может обойти лимит ошибками; цена — редкая потеря единицы квоты
при сбое. Сутки считаются по UTC.

## ADR-014. Импорт лексикона добавляет и обновляет, но не удаляет

**Статус:** принято.

**Контекст.** Лексикон общий, а на его значения ссылаются личные данные (`user_vocabulary_item`,
`meaning_content`, `sense_selection`). Повторный импорт не должен менять или терять `id` значений.

**Решение.** Лексемы, формы, значения и переводы заливаются через `INSERT … ON CONFLICT`: значение
идентифицируется по `source_external_id` (хэш части речи и глоссы), обновляется только изменившееся.
Лексема, созданная fallback-источником (`free_dictionary`, `ai`), при появлении в Wiktionary
переходит под источник `wiktionary` (текст и тип берутся из словаря), а её значения сохраняют своё
поле `source`. Устаревшие значения и формы из прежних импортов не удаляются.

**Последствия.** Данные безопасны для ссылок, но после смены параметров импорта (N, правила отбора)
старые строки остаются; для чистой пересборки на пустой БД лексикон очищается вручную
(`TRUNCATE lexeme CASCADE`). Удаление устаревших строк, не используемых личными данными, в backlog.
